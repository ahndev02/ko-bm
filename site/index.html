KoBALT-700 benchmark runs

KoBALT-700 is a set of 700 expert-written Korean multiple-choice items across five linguistic domains. This page reports our own evaluation runs: what was tested, how, and what came out. It is a record, not a ranking.

Reasoning ablations

These are configuration experiments, kept separate from the primary results above. They are not model ranks: the same model is run with a different provider reasoning setting, and everything else is held fixed.

Reliability: invalid outputs and latency

An output counts as invalid when no single A–J choice can be extracted from it; invalid outputs count as wrong. Latency depends on the endpoint and deployment used for each run (provider API, routing tier, or local server) and should not be read as intrinsic model speed.

Method

  • Decoding: deterministic settings throughout — do_sample: false (greedy where the backend supports it; temperature: 0.0 on the API backends), with a max_new_tokens: 2048 cap. All runs share one prompt template (hash 39412071…; full hash in each evidence snapshot).
  • Prompt: Korean chain-of-thought prompt, shown here exactly as sent (with {question} replaced by the item text):

English translation (for reference only; models saw the Korean above): “Think through the following problem and choose the correct answer from the 10 options (A, B, C, D, E, F, G, H, I, J). [question] Your answer must strictly keep the following form: it must end with ‘정답은 [choice]입니다.’ ([The answer is [choice].]), where [choice] is one of A–J. Answer: To solve this, let us think slowly.”

  • Answer extraction: strict regular expression 정답은\s*(.*?)\s*입니다; from each match, A–J letters are collected in order. The run is correct only if the extracted string is exactly the gold letter.
  • Invalid outputs count as wrong. A missing or malformed final-answer phrase is scored 0, not excluded.

Reproduce & evidence

Each run directory keeps a config snapshot and a scored results file; the per-run cards above link to both. This page itself is generated from those files — raw model predictions are not published, so only the snapshot and results links below exist.

Regenerate the data file with:

python3 site/build.py

This reads completed run directories under runs/ and writes site/results.json plus the evidence copies under site/data/runs/<run>/. Incomplete runs are skipped and listed separately.

Limitations

  • KoBALT-700 is a public benchmark, so prior exposure of these items in model training (contamination) is unknown and cannot be ruled out.
  • One run per configuration: there is no measure of run-to-run repeatability, and close scores may not reflect a real difference.
  • The recorded dataset revision is 0.0.0, a placeholder — it is not content-addressed, so exact dataset identity rests on the benchmark release rather than a pinned hash.
  • Reasoning policies differ across runs (provider default, explicit minimal effort, disabled); comparisons across those settings are about configuration, not models alone.
  • Small subgroups are noisy: several subclasses have fewer than 20 items, and single items can move those percentages by several points. Treat the domain and level tables above as descriptive.
